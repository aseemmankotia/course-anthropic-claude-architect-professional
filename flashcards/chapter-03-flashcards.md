## Chapter 3: Integration II: Retrieval, Identity, and Event-Driven Patterns — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Message Batches API — max requests per batch? | 100,000 requests per batch, capped at 256MB total batch size. Exam tip: processing is asynchronous, typically completing within 24 hours, at up to 50% cost discount vs synchronous calls. |
| 2 | Delegated auth vs service account — key difference? | Delegated: agent acts AS the authenticated user, inheriting that user's exact permission scope. Service account: agent acts as itself with fixed permissions. Exam tip: use delegated auth whenever per-user data visibility must be enforced. |
| 3 | When should you use event-driven integration over batch? | When freshness/latency matters and changes are frequent/unpredictable (e.g., price/stock). Batch suits high-volume, low-change-frequency data. Exam tip: hybrid per-data-source strategies are usually the 'best' answer. |
| 4 | Standard chunk overlap percentage in RAG pipelines? | Commonly 10-20% of chunk size. Exam tip: overlap prevents loss of context spanning chunk boundaries — a frequent exam gotcha. |
| 5 | Hybrid search = ? | Dense vector (semantic) retrieval + sparse/keyword (BM25) retrieval, merged/reranked. Exam tip: use for queries mixing conceptual language and exact-match tokens (SKUs, IDs, codes). |
| 6 | MCP (Model Context Protocol) auth model for remote servers? | OAuth 2.1-based authorization flow for connecting agents to remote MCP servers. Exam tip: local/stdio MCP servers typically rely on the host process's own credentials, not OAuth. |
| 7 | Legacy mainframe with flat-file FTP export, no API — best integration pattern? | Scheduled polling job matched to the source's own export cadence, parsing the file into the pipeline. Exam tip: don't assume legacy systems can be replaced with webhooks/APIs — polling/batch is the expected answer. |
| 8 | Why avoid a single shared service account for a multi-tenant agent accessing per-user-permissioned data? | It grants broader access than any individual requesting user should have, breaking least-privilege and risking cross-user data leakage. Exam tip: use per-user delegated OAuth tokens instead. |
| 9 | RAG freshness: nightly batch re-embedding of a document that changes every few minutes — exam verdict? | Wrong approach. Fast-changing data needs event-driven/webhook-triggered re-embedding; nightly batch leaves it stale up to 24 hours. Exam tip: match sync strategy to each source's own change frequency. |
| 10 | Message Batches API cost benefit? | Up to 50% cost discount vs standard synchronous calls, in exchange for asynchronous processing (results within 24 hours). Exam tip: pick for large-volume, non-latency-sensitive workloads. |
| 11 | Webhook-based event-driven integration — key architectural requirement often tested? | Idempotency handling and retry/dedup logic, since webhook deliveries can be duplicated or arrive out of order. Exam tip: this is the main complexity cost vs batch integration. |
| 12 | Query mixes exact SKU/part numbers with conceptual language — why does pure dense-embedding retrieval fail? | Exact-match tokens (SKUs, IDs) are poorly captured by semantic embeddings alone. Fix: hybrid search combining dense + sparse (BM25) retrieval. Exam tip: pure semantic search is a common wrong-answer trap here. |
