## Chapter 5: Solution Design II: Resilience, Scaling, and Reference Architectures — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | SLA 99.9% vs 99.99% — approximate allowed downtime per month? | 99.9% ≈ ~43 minutes/month downtime allowed. 99.99% ≈ ~4.3 minutes/month. Exam tip: each added '9' roughly cuts allowed downtime by 10x — used to justify multi-region HA cost tradeoffs. |
| 2 | Circuit breaker: what are the three standard states? | CLOSED (normal traffic) → OPEN (requests blocked after failure threshold) → HALF-OPEN (limited trial requests after cooldown). Exam tip: HALF-OPEN is the step students forget, assuming it jumps straight back to CLOSED. |
| 3 | Exponential backoff with jitter — why add jitter? | Pure exponential backoff causes synchronized retry spikes ('thundering herd') when many clients retry at the same intervals. Jitter randomizes retry timing to spread load. Exam tip: always expect 'with jitter' as the correct answer over plain backoff. |
| 4 | Active-active vs active-passive multi-region — key difference? | Active-active: all regions serve live traffic simultaneously (higher availability, more complex data sync). Active-passive: one region serves traffic, the other stands by for failover (simpler, slightly higher failover latency). Exam tip: data residency constraints often force active-passive per region instead of global active-active. |
| 5 | Prompt caching vs semantic caching — what's the difference? | Prompt caching reuses processed tokens for an identical/static prefix (e.g., system prompt) to cut cost/latency on repeated calls. Semantic caching stores past responses and matches new queries by meaning (not exact text) to avoid reprocessing similar questions. Exam tip: use both together in high-volume RAG systems. |
| 6 | HTTP 429 response — what should the client do? | Respect the Retry-After header (if present) and apply exponential backoff with jitter before retrying; queue excess requests rather than retrying immediately. Exam tip: 429 means rate-limited/quota-exceeded, NOT a transient server error — treat it differently from 500s. |
| 7 | Enterprise RAG assistant reference architecture — core components? | Ingestion pipeline → chunking/embedding → vector DB → retriever → reranker → LLM generation → guardrails/filtering → caching layer → response. Exam tip: reranker and guardrails stages are the ones students forget to include. |
| 8 | Multi-system agentic workflow — core components? | Orchestrator agent → task planner → tool-calling sub-agents → shared state/memory store → message queue between agents → human-in-the-loop checkpoint (optional) → final output aggregator. Exam tip: resilience (retries/circuit breakers) must be applied per tool call, not just at the orchestrator level. |
| 9 | Fallback/degradation ladder — correct order? | Primary (large) model → smaller/cheaper model tier → cached or templated response → graceful error message. Exam tip: a hard failure with no intermediate steps is always the wrong-answer choice in scenario questions. |
| 10 | Token bucket rate limiter — what does it do? | Allows bursts up to a bucket capacity while enforcing a steady average refill rate, used to smooth outbound requests against a provider's quota per API key. Exam tip: pairs with a gateway pooling multiple keys for horizontal scaling past a single quota. |
| 11 | Cached vs fresh prompt tokens — cost implication? | Across major LLM providers, reused/cached prompt tokens are billed at a reduced rate compared to fresh input tokens. Exam tip: caching saves the most on workloads with long static prefixes and high call volume; it saves little on unique, one-off prompts. |
| 12 | Capacity planning for known peak events — best practice? | Pre-warm/pre-provision capacity ahead of the predictable spike window, and layer autoscaling on top for any overflow beyond forecast. Exam tip: pure reactive autoscaling alone is the wrong answer for predictable, scheduled spikes due to scale-up lag. |
